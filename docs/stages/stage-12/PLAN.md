## 目标与本阶段边界

建立 Debug/Release 分离的正式导出、版本号、构建元数据、可复现脚本、包内清单和 SHA-256；检查未批准素材、测试夹具、调试入口、缓存、SDK 私密内容和凭据没有打包。

在无 Godot 编辑器的干净 Windows 环境验证启动、操作、设置、存档、退出及适用的安装/卸载路径。不能只在开发机器运行十帧 Debug 构建就勾此项。

完成 Steam 平台抽象、适用的成就/云存档映射/手柄准备，SDK 或运行环境缺失时提供测试 fallback，但不得把 fallback 通过写成真实 Steam 后台已配置。整理商店文案草案、真实截图、预告片镜头、封面候选、依赖许可证与 AI/权利清单。

收费、登录/2FA、身份/税务/银行资料、协议签署、公开商店提交和向真实玩家开放版本，需要用户按原契约处理。它们不阻止本地技术与素材准备，但未完成的外部事项必须明示，不伪造后台通过。

**退出门：**逐项满足 v2 §14 的 RC1 DoD；RELEASE_READINESS 的通过项有当前适用证据；交付 RC1 ZIP、checksum、发布说明和已知问题；在安全祖先链上完成授权的 main/tag/push。只有真正达到条件才创建 `capybara-rc1`，不要提前打 RC 标签。

## 退出质量门

交付：

- 正式 Windows 导出预设和可复现构建脚本。
- Debug/Release 配置分离，正式构建隐藏调试工具。
- 版本号、构建元数据、许可证和第三方声明。
- Steam 接口抽象、成就、云存档映射和手柄支持；无 SDK 时保留可测试 fallback。
- 商店文案草案、真实截图、预告片镜头清单和封面资产候选。
- AI 内容清单和权利清单。
- 干净机器安装、启动、存档、退出和卸载检查。
- RC1 ZIP、校验值、发布说明和已知问题。

Steam 后台缴费、身份、税务、银行信息、最终公开发布和商店提交属于硬阻塞，需要用户本人处理；其余技术和素材准备由 Codex完成。

退出标准：满足第 14 节全部 Release Candidate Definition of Done，并创建 `capybara-rc1` tag。

## Steam 技术与提交实施范围

CAP-0610包含可关闭平台抽象、适用的10–20基础成就、Overlay、语言/时长映射及无SDK可测试fallback。CAP-0701仅同步稳定存档，验证双设备冲突/旧云档迁移，排除设置分辨率、日志、缓存/临时截图；CAP-0702覆盖Steam Input/控制器提示、1280×800、睡眠恢复输入音频与存档。Steam Deck类分辨率不等于实机认证。排行榜/Workshop/Remote Play不属于RC必需；联机继续永久不做。

CAP-0703包含[商店草稿](STORE_DRAFT.md)、真实建设/种植/钓鱼/泡水/探索截图、30–60秒实机预告片与胶囊候选。名称/商标与当前Steamworks要求提交前按官方资料重核；不能凭概念图承诺未实现功能。CAP-0704逐项核对发布视觉/声音/文本AI清单、字体音频插件授权及无运行时AI事实，禁止虚构人工审核。

AUT-1200和CAP-0705记录源码/构建号、Debug/Playtest/Release隔离、depot/redistributables配置、干净非管理员Windows安装/启动/保存/退出/卸载、包内排除调试菜单/测试存档/源素材/SDK/秘密。发布前完成内容冻结与旧档演练；Steam登录/费用/主体身份/税务/银行/协议、公开商店或向真实玩家开放由用户处理。

上线日期倒排、发布当天普通账号安装及论坛监控、首日补丁/后续支持属于授权后的运营工作，不能因为旧清单写了日期就自动公开发布。技术和素材准备持续推进，最终可交付RC1无需假称后台已审核。
